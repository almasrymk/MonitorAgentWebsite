# قائمة الإطلاق

الموقع مش بيستقبل دفع حقيقي غير لما كل بند هنا يتعلّم عليه، و**صاحب المشروع يوافق كتابةً** على التحويل في الآخر. البنود اللي فيها (👤) محتاجة قرار أو حاجة من صاحب المشروع نفسه.

## 1. قرارات مفتوحة
- [ ] 👤 مزوّد الدفع: Paymob (المقترح، للعملاء في مصر بالجنيه) أو Stripe. وبعدها عقد التاجر وبيانات الـ API.
- [ ] 👤 طريقة دخول الموقع على LicensingPlatform: حساب خدمة (المقترح) بصلاحيات إصدار الرخص بس.
- [ ] 👤 الاستضافة: Azure (المقترح: App Service + Azure SQL + Key Vault) أو سيرفر خاص بـ Docker.
- [ ] 👤 الدومين، والإيميل اللي بيبعت منه الموقع (SPF و DKIM و DMARC).
- [ ] 👤 تغيير مفتاح الـ API اللي اتكتب قبل كده في ريبو UBGMonitor العام (لسه مطلوب).

## 2. البيئة
- [ ] بيئة staging نسخة من الإنتاج، وكل نشر بيعدّي عليها الأول.
- [ ] كل الأسرار في Key Vault (أو متغيرات بيئة محمية)، ومفيش ولا سر في الريبو أو في الـ image.
- [ ] `ASPNETCORE_ENVIRONMENT=Production`. ده بيقفل مزوّد الـ Sandbox تلقائيًا.
- [ ] HTTPS بس، و HSTS، والـ API والتطبيقات تحت نفس الدومين (الكوكيز `__Host-`).
- [ ] `Support:DemoRequestsEmail` على إيميل المبيعات الحقيقي بدل القيمة الافتراضية `sales@monitoragent.local`، عشان طلبات العرض التوضيحي توصلهم أول بأول.
- [ ] `Cors:Origins` و `Portal:Url` مظبوطين، والـ reverse proxy بيبعت IP العميل الحقيقي عشان حدود الطلبات.
- [ ] WAF أو على الأقل حد طلبات في الـ proxy قدام الموقع.
- [ ] حساب أدمن أول عن طريق `Identity:BootstrapAdmin*`، وبعدين تتشال من الإعدادات. الأدمن يفعّل التحقق بخطوتين.

## 3. الاختبارات (CI أخضر على main)
- [ ] Unit و Architecture و API و E2E بالعربي والإنجليزي.
- [ ] CodeQL و Gitleaks: صفر Critical أو High.
- [ ] Trivy على الـ image: صفر Critical أو High ليها حل.
- [ ] ZAP الليلي: صفر High.
- [ ] Lighthouse: الأداء 90 أو أكتر، و LCP أقل من 2.5s، و CLS أقل من 0.1.
- [ ] axe: صفر مخالفات.
- [ ] k6 على staging: p95 أقل من 300ms (و150ms لملف التحديثات)، والأخطاء أقل من 0.1%. وSoak 8 ساعات من غير تدهور أكتر من 10%.

## 4. اختبار الاختراق الخارجي
- [ ] 👤 اختيار الجهة والموافقة على العرض.
- [ ] النطاق: الموقع والبوابة ولوحة الأدمن والـ API والـ webhooks وبرنامج العميل وتحديثاته، على staging.
- [ ] كل Critical و High اتصلّح واتعاد اختباره، والتقرير النهائي محفوظ.

## 5. التشغيل
- [ ] النسخ الاحتياطي شغّال حسب [backup-restore.md](backup-restore.md)، وتدريب استرجاع حقيقي على staging نجح في أقل من ساعة.
- [ ] التنبيهات في [monitoring.md](monitoring.md) شغّالة، واتجرّب تنبيه واحد على الأقل يوصل للموبايل.
- [ ] مسؤول مناوبة ورقم تليفون للطوارئ.
- [ ] الرجوع لنسخة سابقة من النشر اتجرّب على staging.

## 6. القانوني والمحتوى
- [ ] 👤 الشروط وسياسة الخصوصية وسياسة الاسترداد مكتوبين ومراجَعين، ومنشورين من الـ CMS.
- [ ] 👤 بيانات الفاتورة (اسم الشركة، والرقم الضريبي، والعنوان) صح، ونظام الترقيم مقبول عند المحاسب.
- [ ] تنزيل ومسح بيانات العميل شغّالين (ADR-016).

## 7. التحويل للدفع الحقيقي
- [ ] بيانات المزوّد الحقيقية في Key Vault، وعنوان الـ webhook متسجّل عنده، وسر التوقيع متطابق.
- [ ] عملية بمبلغ صغير بكارت حقيقي على الإنتاج: الدفع، والرخصة، والفاتورة، والإيميلين. وبعدين استرداد كامل ليها.
- [ ] Webhook مكرر ومتأخر وبتوقيع غلط، كلهم اتجربوا على staging مع المزوّد الحقيقي في وضع الاختبار.
- [ ] 👤 **موافقة مكتوبة من صاحب المشروع على التحويل**، بالتاريخ.

## بعد الإطلاق بأسبوع

- [ ] تثبيت أرقام الأداء النهائية حسب الاستخدام الحقيقي.
